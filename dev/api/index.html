API reference

Optimizer

OptimizationSNOPT.SnoptOptimizer — Type
SnoptOptimizer(; kwargs...)

Configure SNOPT for an Optimization.jl problem.

SNOPT solves problems of the form:

minimize    f(x)
subject to  g_L <= g(x) <= g_U
            x_L <= x <= x_U

Optimizer keywords

Iteration limits must be positive integers. Print levels must be nonnegative integers. All tolerances must be positive, finite real numbers.

  • major_print_level::Int = 1: SNOPT's major-iteration output level.
  • minor_print_level::Int = 0: SNOPT's minor-iteration output level.
  • major_iterations_limit::Int = 1000: Maximum major iterations.
  • minor_iterations_limit::Int = 500: Maximum minor iterations.
  • major_optimality_tolerance::Float64 = 1e-6: First-order optimality tolerance.
  • major_feasibility_tolerance::Float64 = 1e-6: Nonlinear feasibility tolerance.
  • minor_feasibility_tolerance::Float64 = 1e-6: Linear subproblem feasibility tolerance.
  • derivative_option::Int = 1: SNOPT derivative mode. Valid values are 1, 2, and 3.
  • hessian::String = "full_memory": Use "full_memory" or "limited_memory".
  • additional_options::AbstractDict: Other SNOPT options.

Additional option keys may be strings or symbols. Symbol underscores become spaces. Values may be integers, floats, strings, symbols, or nothing.

The constructor rejects additional options that duplicate explicit keywords. It also normalizes all option keys and values.

Solve keywords

These common Optimization.jl keywords override related optimizer fields:

  • maxiters overrides major_iterations_limit.
  • abstol overrides major_optimality_tolerance.
  • reltol overrides minor_feasibility_tolerance.
  • verbose or show_trace prints an iteration trace.
  • trace_level selects SnoptTraceMinimal or SnoptTraceAll.
  • store_trace = Val(true) stores records in solution.trace.

Side effects and concurrency

SNOPT owns one active Fortran workspace per process. This package serializes workspace creation and solves. Threaded callers are safe, but solves run sequentially.

When SNOPT is available, construction validates options with a temporary workspace. This closes any manually managed SNOPT.jl workspace. Construct the optimizer before creating a low-level workspace.

Examples

using OptimizationBase, OptimizationSNOPT

opt = SnoptOptimizer()

opt = SnoptOptimizer(
    major_iterations_limit = 2_000,
    major_optimality_tolerance = 1.0e-8,
    additional_options = Dict("Linesearch tolerance" => 0.9),
)

result = solve(prob, opt; maxiters = 500, abstol = 1.0e-8, verbose = true)

See the SNOPT option reference for every native option.

Traces

OptimizationSNOPT.SnoptTraceMinimal — Function
SnoptTraceMinimal(; print_frequency=1, store_frequency=1)

Record scalar progress values during a solve.

Both frequencies must be positive integers. print_frequency controls printed rows. store_frequency controls rows retained in SnoptTrace.

source
OptimizationSNOPT.SnoptTraceAll — Function
SnoptTraceAll(; print_frequency=1, store_frequency=1)

Record scalar progress, points, and constraint values during a solve.

Both frequencies must be positive integers. Full traces copy the point and constraint arrays for each stored row.

source
OptimizationSNOPT.SnoptTraceEntry — Type
SnoptTraceEntry

One stored SNOPT iteration.

Unavailable numeric values are NaN. The final row may use nothing for vectors or status data that SNOPT did not provide.

source
OptimizationSNOPT.SnoptTrace — Type
SnoptTrace

Stored iteration records and the trace level that produced them.

Access a solve trace through solution.trace after passing store_trace = Val(true) to solve.
